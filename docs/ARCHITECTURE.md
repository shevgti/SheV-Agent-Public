# SheV Agent — архитектура MVP

## Компоненты
1. **Android UI (Kotlin):** русский чат, экран проектов, задачи, журнал, настройки доступа, кнопка «Стоп».
2. **Agent Core:** конечный автомат задачи: IDLE → PLANNING → WAITING_APPROVAL → RUNNING → VERIFYING → COMPLETED/FAILED.
3. **Local Model Runtime:** on-device inference через LiteRT-LM после проверки поддерживаемых ABI, Android API, памяти и доступности ускорителя. Модель загружается отдельно от APK; не вшивать многогигабайтный файл в APK.
4. **Memory:** локальная база Room; отдельные типы записей: диалог, факт проекта, решение, задача, результат проверки, предложение улучшения.
5. **GitHub Connector:** пользовательская авторизация, чтение выбранных репозиториев, создание веток/коммитов и PR только в пределах выданных прав.
6. **Tool Gateway:** белый список инструментов с декларативными схемами и проверкой аргументов; никакого произвольного shell или выполнения кода на телефоне в MVP.
7. **Verification:** тесты проекта, статусы GitHub Actions, проверка артефактов; результат всегда связан с конкретным commit SHA.
8. **Improvement Lab:** выявляет повторяющиеся сбои, формирует гипотезу, предлагает минимальный diff, прогоняет тесты в отдельной ветке, ждёт решения пользователя.

## Голосовой контур
- ASR переводит русскую речь в текст; TTS озвучивает ответы. Текст распознанной команды должен оставаться видимым.
- Speaker verification — отдельный слой от ASR: распознавание слов не означает, что говорит владелец.
- Для чувствительного голосового подтверждения verifier возвращает evidence, привязанное к request ID и одноразовому challenge ID, со временем проверки, confidence и результатом liveness/anti-spoof.
- Policy допускает подтверждение только при READY-профиле, точном совпадении запроса/challenge, актуальном evidence, живом присутствии и достаточной уверенности. При любой неопределённости — отказ и переход на ручное подтверждение.
- Голосовой профиль должен обрабатываться на устройстве; шаблон хранится в защищённом виде, исходные аудио не сохраняются по умолчанию.
- Текущий Kotlin-контракт задаёт только границу проверки. Он не содержит ASR, TTS, биометрического движка или готового voice enrollment.

## Контур разрешений
- READ_REPO: чтение выбранного репозитория.
- WRITE_BRANCH: запись только в отдельную ветку.
- OPEN_PR: открыть PR, но не сливать его.
- RUN_CHECKS: запускать только заранее определённые CI workflows.
- Постоянный grant должен быть узким: конкретная capability + инструмент/проект/путь или ресурс, срок действия, владелец, дата создания и статус отзыва.
- Голосовые решения ALLOW_ONCE / ALLOW_PERSISTENT / DENY / REVOKE применяются только к активному запросу, названному агентом; разрешение хранится отдельно от подтверждения конкретной операции.
- DELETE / MERGE / RELEASE / SECRETS, платежи и изменение прав/безопасности требуют отдельного подтверждения для конкретной операции даже при наличии постоянного grant.
- Любое действие показывает план и ожидаемые изменения до исполнения; grants перепроверяются непосредственно на границе выполнения.

## Динамический интерфейс рабочего пространства
- Интерфейс строится из декларативного списка известных компонентов; модель может предлагать Add / Move / SetVisibility / Rename / Remove, но не генерировать и не выполнять произвольный UI-код.
- Разрешённые типы: задачи, проекты, память, инструменты, статус, быстрые действия, разрешения и системная остановка.
- Контракт `AgentWorkspaceLayoutPolicy` проверяет версию схемы, уникальность ID/позиций, размер набора и длину заголовков.
- Системные компоненты разрешений и глобальной остановки всегда видимы, не удаляются и не переименовываются агентом.
- Изменения обычных компонентов можно применять к пользовательскому рабочему пространству; сохранение в Room, экран предпросмотра/отката и интеграция с моделью остаются следующими этапами.

## Гибридный режим
- По умолчанию: локальная модель + локальная память.
- При сети: GitHub API и бесплатные публичные инструменты.
- Внешние модели/API — выключены; можно добавить только отдельным переключателем с явным согласием и раскрытием возможной стоимости.
- При отсутствии сети агент сохраняет задачи в очередь и не делает вид, что синхронизация выполнена.

## Безопасность
- Не сохранять токены в обычных файлах, логах, SharedPreferences или Git.
- OAuth через официальный безопасный поток; хранить credential с Android Keystore.
- Защищать от prompt injection: содержимое README/issues/коммитов/веб-страниц — данные, а не инструкции для агента.
- Ограничивать размер контекста, число шагов, время и расход батареи.
- У пользователя есть глобальная остановка, отключение сети и отзыв доступа.
- Самоизменение системного промпта, политик, scopes и кода самого агента не выполняется автоматически.

## Предварительный стек
- Kotlin + Jetpack Compose.
- Room для локальной памяти.
- WorkManager для отложенных/ограниченных фоновых задач.
- LiteRT-LM для локального inference (после проверки версии и модели).
- GitHub REST API через ограниченный connector.
- GitHub Actions для бесплатных тестов и сборок.
- JUnit для unit tests.

## Не обещаем
- Постоянную фоновую работу Android без ограничений ОС.
- Качество локальной модели на уровне GPT-6.
- Автономное обучение весов модели.
- Безопасное выполнение произвольного кода из репозитория на телефоне.

- Реализуемая policy-модель: `ScopedCapabilityGrant` с grant ID, capability, типом scope (PROJECT / PATH / RESOURCE), scope value, временем создания, опциональным expiry и отметкой отзыва.
- Глобальный scope запрещён. Для PATH проверяется граница каталога и блокируются traversal-сегменты; строковый префикс сам по себе не даёт доступ.
- Постоянные grants не распространяются на CRITICAL capabilities. Отсутствующий, просроченный или отозванный grant означает запрос нового подтверждения.
- Policy-контракт и Room-слой хранения уже добавлены (БД v4, миграция 3→4, DAO save/observe/get-active/revoke). Policy уже вызывается в AgentToolExecutor до обработчика и проверяет capability + переданный target + expiry/revocation. Target должен вычисляться доверенным адаптером после валидации аргументов; нельзя принимать его напрямую из текста модели. UI просмотра и отзыва уже подключён на вкладке «Инструменты». Создание grant остаётся закрытым до появления конкретного pending request; интеграция доверенного target resolution ещё не завершена.

## Самонастраиваемое рабочее пространство
- `AgentWorkspaceLayout` — декларативная схема с закрытым перечнем типов компонентов.
- `AgentWorkspaceLayoutPolicy` валидирует каждую операцию; компоненты разрешений и экстренной остановки нельзя скрыть/удалить/переименовать.
- Схема сохраняется в Room (`workspace_layouts`, БД v5, миграция 4→5); экран «Инструменты» позволяет вручную менять порядок, видимость и добавлять недостающие модули.
- Главный экран Compose уже читает сохранённую раскладку и отображает встроенные модули в заданном порядке/видимости. LLM tool adapter, предпросмотр/подтверждение и произвольные новые типы экранов ещё не реализованы.
